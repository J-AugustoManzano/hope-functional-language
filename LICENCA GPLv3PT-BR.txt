A GNU General Public License é uma licença livre com copyleft para software 
e outros tipos de obras[cite: 8].

As licenças para a maioria dos softwares e outras obras de natureza prática

Quando falamos de software livre (free software), queremos dizer liberdade, 
não preço[cite: 13]. Nossas Licenças Públicas Gerais são projetadas para garantir sua 
liberdade de distribuir cópias de software livre (e cobrar por elas, se

software ou usar partes dele em novos programas livres, e garantir que 
você saiba que pode fazer essas coisas[cite: 14].

Para proteger seus direitos, precisamos impedir que outras pessoas neguem 
esses direitos a você ou peçam que você abra mão deles[cite: 15]. Portanto, você tem 
certas responsabilidades se distribuir cópias do software ou modificá-lo: 
a responsabilidade de respeitar a liberdade dos outros[cite: 16].

Por exemplo, se você distribuir cópias de um programa, gratuitamente ou 
por uma taxa, você deve transferir para os destinatários as mesmas 
liberdades que você recebeu[cite: 17]. Você deve certificar-se de que eles também 
recebam ou possam obter o código-fonte[cite: 18]. E você deve mostrar a eles estes 
termos para que eles possam conhecer seus direitos[cite: 19].

Os desenvolvedores que usam a GNU GPL protegem seus direitos em duas 
etapas: (1) afirmando o direito autoral do software e (2) oferecendo a 
você esta licença que lhe dá permissão legal para copiar, distribuir 
e/ou modificá-lo[cite: 20].

Para a proteção de autores e desenvolvedores, a GPL explica claramente que 
não há garantia para este software livre[cite: 21]. Para o bem dos usuários e 
autores, a GPL exige que as versões modificadas sejam marcadas como 
alteradas, para que seus problemas não sejam atribuídos erroneamente 
aos autores de versões anteriores[cite: 22].

Alguns dispositivos são projetados para negar aos usuários o acesso para 
instalar ou executar versões modificadas do software em seu interior, embora 
o fabricante possa fazê-lo[cite: 23]. Isso é fundamentalmente incompatível com o objetivo 
de proteger a liberdade dos usuários de modificar o software[cite: 24]. O padrão

Finalmente, todo programa é constantemente ameaçado por patentes de software[cite: 28]. 
Os Estados não devem permitir patentes que restrinjam o desenvolvimento e o 
uso de software em computadores de uso geral; mas, naqueles que o fazem,

“Modificar” uma obra significa copiar ou adaptar parte ou a totalidade da obra

“Divulgar” uma obra significa fazer qualquer coisa com ela que, sem permissão,

“Transmitir” uma obra significa qualquer tipo de divulgação que permita a

1. Código-Fonte.
----------------

O “código-fonte” de uma obra significa a forma preferencial da obra para 
fazer modificações nela[cite: 44]. “Código-objeto” significa qualquer forma não-fonte 
de uma obra[cite: 45].

Uma “Interface Padrão” significa uma interface que seja um padrão oficial 
definido por um órgão de padrões reconhecido ou, no caso de interfaces 
especificadas para uma linguagem de programação específica, uma interface 
amplamente utilizada entre os desenvolvedores que trabalham nessa linguagem[cite: 46].

As “Bibliotecas do Sistema” de uma obra executável incluem qualquer coisa, 
exceto a obra como um todo, que (a) esteja incluída na forma normal de um 
pacote de Componente Principal e (b) sirva apenas para permitir o uso da 
obra com esse Componente Principal, ou para implementar uma interface padrão 
cuja implementação esteja disponível publicamente na forma de código-fonte[cite: 47]. 
Um “Componente Principal”, neste contexto, significa um componente essencial 
principal (kernel, sistema de janelas, etc.) do sistema operacional específico 
(se houver) no qual o executável é executado, ou um compilador usado para 
produzir a obra, ou um interpretador de código-objeto usado para fazê-lo funcionar[cite: 48].

A “Fonte Correspondente” de uma obra na forma de código-objeto significa todo 
o código-fonte necessário para gerar, instalar e (para uma obra executável) 
operar o código-objeto e modificar a obra, incluindo scripts para controlar 
tais atividades[cite: 49]. No entanto, isso não inclui as Bibliotecas do Sistema da obra, 
ou ferramentas de uso geral ou programas de disponibilidade geral gratuita que 
são usados sem modificação para realizar essas atividades, mas que não fazem 
parte da obra[cite: 50]. Por exemplo, a Fonte Correspondente inclui arquivos de 
definição de interface associados aos arquivos de origem da obra, e o 
código-fonte de bibliotecas compartilhadas e sub-rotinas vinculadas 
dinamicamente (links dinâmicos) para as quais a obra foi projetada 
especificamente para exigir[cite: 51].

A Fonte Correspondente não deve incluir nada que os usuários possam regenerar 
automaticamente a partir de outras partes da Fonte Correspondente[cite: 51].

A Fonte Correspondente de uma obra na forma de código-fonte é a própria obra[cite: 52].
